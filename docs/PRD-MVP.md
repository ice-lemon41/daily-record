## 0. 一句话定义

**一个单机、本地优先的「随手记」：打开就能写一句话，自动识别 #标签与指标数字，按时间线和日历回看，数据可完整导出导入，可装到桌面并离线使用。**

---

## 1. 背景

前期调研（`docs/日常记录-开源项目调研.md`）得到三条直接影响本产品的结论：

1. **功能膨胀会杀死核心路径**。侠客日记被用户吐槽「打开要四五秒，只需要一个能写字的本地便签」。
2. **本地优先是共识，但纯本地数据很脆弱**。导出/导入不是设置页的附属功能，而是数据安全的唯一退路。
3. **升级迁移与数据丢失是最大风险**。Easy Diary 的 Realm→Room 迁移事故说明：数据结构越简单、派生逻辑越可重建，风险越低。

因此 MVP 不追求功能覆盖，只验证一件事：**产品负责人本人能否连续 7 天真的用它记录**。

## 2. 目标与非目标

### 2.1 目标

| 编号 | 目标 | 衡量方式 |
|---|---|---|
| G1 | 验证「天天用」 | 连续 7 天，每天至少 1 条真实记录 |
| G2 | 主路径足够短 | 打开 → 写 → 提交 ≤ 3 步，10 秒内完成 |
| G3 | 数据不会凭空消失 | 导出 → 清空 → 导入 round-trip 字段不丢 |
| G4 | 手机上是「像 App 的网页」 | 可安装、断网可读写、冷启动 ≤ 2 秒 |

### 2.2 非目标

- 不做多用户、账号、云同步、分享；
- 不做商业化、增长、留存分析；
- 不做跨平台（iOS / 桌面端不承诺体验）；
- 不替代长文写作工具，不追求富文本排版；
- 不在首版做任何图表与统计。

## 3. 用户与场景

**主用户**：产品负责人本人。Android 手机，主要在碎片时间使用，不想维护服务器，也不想注册账号。

**典型场景**：

| 场景 | 行为 | 对 MVP 的要求 |
|---|---|---|
| 通勤路上想到一句话 | 掏出手机，打开即写，一句话提交 | 输入框在首屏、无需进入编辑页 |
| 晚上补记今天发生的事 | 从日历点今天，或在输入框改时间 | 时间可任意修改、可补记 |
| 忘了写昨天 | 日历点昨天 → 补记 | 日历支持按天筛选与补记 |
| 想知道上周记了什么 | 搜索关键词，或点标签 | 关键词搜索 + 标签筛选 |
| 换手机 / 清缓存前 | 导出一个文件，之后导入 | 完整导出 + 可恢复的导入 |
| 地铁里没信号 | 继续记录 | 离线可用、本地写入 |

---

## 4. 产品原则

1. **正文即真相**：标签与数值都从正文解析，随时可从正文重建；不出现「正文改了、结构化字段没改」的分裂。
2. **打开即写**：首屏就是输入框，任何跳转都不应该发生在「开始写」之前。
3. **单机优先，导出是核心功能**：不假设有服务器，不假设永远不换设备。
4. **功能冻结**：MVP 期间只允许「替换」，不允许「追加」。新想法一律进 P1 池。

## 7. 功能需求

### FR-01 快速记录

**规则**

1. 首屏输入框获得焦点后可直接输入，支持多行。
2. 提交方式：点击「记录」按钮；桌面端支持 `Ctrl/Cmd + Enter`。移动端回车换行，不提交。
3. 提交前检查：去除首尾空白后为空 → 不写入、不报错、不清空。
4. 写入必须在本地存储事务完成后，才清空输入框并显示新条目；写入失败 → 保留正文并提示「保存失败，请重试」。
5. 时间归属默认「当前时间」；用户可在提交前改成任意日期与时分。
6. 提交后时间归属重置为「现在」，避免连续多条记到旧日期。
7. 记录创建后立即出现在时间线顶部，无需刷新。

**验收**

- 断网状态下完成一次记录，刷新页面后仍在。
- 修改时间归属为昨天后提交，该条出现在「昨天」分组，且输入框时间恢复为「现在」。

### FR-02 草稿保护

**规则**

1. 输入框内容变化后（防抖 300ms）写入草稿，包含正文与当前时间归属。
2. 重新打开页面或刷新时恢复草稿，并提示「已恢复未提交的内容」。
3. 提交成功或用户主动清空输入框后，草稿删除。
4. 全局只有一份草稿，主输入与「补记」共用；补记只是预设了时间归属，不清空已有草稿。

**验收**

- 输入一半 → 锁屏 / 切后台 / 刷新 → 回来内容仍在。
- 提交后刷新，不再出现旧草稿。

### FR-03 标签

**规则**

1. 语法：`#` + 1～20 个非空白、非 `#` 字符。
2. `#` 必须位于行首、空白或标点之后，避免误伤 URL 片段。
3. 末尾的中英文标点（`，。！？、；：,.!?;:` 及右括号）不计入标签名。
4. 英文标签统一小写后存储与去重；中文原样。
5. 一条记录可包含任意数量标签。
6. 正文中标签高亮显示；点击标签 → 时间线进入该标签筛选状态。
7. MVP 不提供标签重命名 / 删除 / 标签列表页；没有记录的标签自然消失。

**验收**

- `今天 #健康 很好` → 解析出 `健康`。
- `见 https://example.com/#/path` → 不解析出标签。
- 点击标签后只显示含该标签的记录，顶部出现可关闭的筛选 chip。

### FR-04 指标数字

**定义**：指标 = 用户自定义的「名称 + 单位」，例如 `体重 / kg`、`花费 / 元`、`睡眠 / 小时`。

**识别规则**

1. 已启用指标出现在正文中，格式为：`指标名` +（0～3 个空格或一个冒号）+ 数字 +（可选空格 + 与指标单位一致的单位文本）。
2. 数字支持整数、小数、负数；单位匹配不区分大小写与中英文全半角。
3. 单位与指标定义不一致 → 不识别，按普通文本保留。
4. 同一条记录中同一指标出现多次 → 只保留最后一次。
5. 正文原文永不改写，识别只产生附加数据。
6. 输入框下方以只读 chip 预览识别结果；修改正文即重新解析，chip 不可单独删除。
7. 时间线条目下方以弱化样式展示识别结果（如 `体重 70.5 kg`），用于确认解析成功。

**新指标建议**

1. 仅当正文出现「2～8 个中英文字符 + 分隔 + 数字 + 白名单单位」，且该名称不是已有指标时，才产生建议。
2. 建议不自动建档、不阻塞保存。保存后以非阻塞提示展示：「发现可能的指标『腰围 80 cm』，要创建吗？」
3. 用户点击「创建」才写入指标定义；点击「忽略」则记录在该条目的 `extra.ignoredSuggestions` 中，不再重复提示。
4. 单条记录最多产生 3 个建议。
5. **降级预案**：若实际使用中误报明显，关闭「新指标建议」，改为仅在设置页手动添加，识别只针对已有指标。

**验收**

- 指标「体重 / kg」存在时，`体重 70.5`、`体重:70.5KG` 均识别；`体重有点重` 不识别；`体重 70.5 斤` 不识别。
- 首次写 `腰围 80cm` → 保存后出现创建建议；忽略后再次打开该条不再提示。
- 修改正文删掉数值后，对应结构化数值也被删除（保存时重建）。

### FR-05 时间线

**规则**

1. 默认按 `occurred_at` 倒序，同一时间按创建时间倒序。
2. 按本地日期分组，标题格式：`今天 / 昨天 / M月D日 周X`；非本年显示年份。
3. 置顶条目集中在顶部「置顶」区，按发生时间倒序，且不再重复出现在日期分组中。
4. 条目展示：时间（时分）+ 正文 +（有则）指标摘要。正文超过 6 行折叠，可展开。
5. 分页加载，每次 50 条，滚动到底自动加载更早内容。
6. 空状态：一句引导 + 一条示例格式说明（不写入真实数据）。
7. 筛选 / 搜索状态下隐藏「置顶」区，结果统一按时间倒序，避免排序心智冲突。

**验收**

- 置顶条目回到顶部且不在原日期重复出现。
- 取消置顶后回到原日期位置。
- 删除条目后立即从所有视图消失。

### FR-06 日历

**规则**

1. 月视图，周一开头，显示当月全部日期与前后月补位。
2. 有未删除条目的日期显示圆点（不显示数量）。
3. 点击日期 → 主界面进入按天筛选，标题显示该日期，提供「在这天补记」。
4. 「在这天补记」→ 聚焦输入框，时间归属预设为该日期 + 当前时分。
5. 再次点击同一天或点击「清除筛选」→ 回到全部时间线。
6. 支持上月 / 下月 / 回到今天。

**验收**

- 在某天补记后，该天圆点出现，点进去能看到该条。
- 跨月、跨年切换日期正确。

### FR-07 搜索与筛选

**规则**

1. 顶栏搜索图标展开搜索框，输入即搜（防抖 200ms），匹配正文与标签名，不区分大小写。
2. 结果按时间线同样规则分组展示，命中关键词高亮。
3. 三种筛选状态互斥：按天、按标签、关键词搜索；任一时刻只生效一种。
4. 每种筛选都在顶部显示可关闭的 chip；关闭后回到全部时间线。
5. 搜索无结果时给出「没有找到相关记录」空状态。
6. MVP 不做高级语法（引号、AND/OR、日期范围）。

**验收**

- 搜「开会」只出现包含该词的记录，词被高亮。
- 在标签筛选下点搜索，标签筛选自动清除。

### FR-08 编辑、删除、置顶、改时间

**规则**

1. 点击条目 → 编辑面板，预填正文与发生时间。
2. 保存时重新解析标签与数值，并更新 `updated_at`。
3. 正文为空不允许保存；如需清空请使用删除。
4. 删除为软删除：二次确认 → 从所有视图移除 → 5 秒内可撤销。
5. 置顶可在编辑面板与条目 `…` 菜单中操作。
6. 发生时间可改到任意日期与时分（含未来）。
7. 单设备场景，不做并发编辑冲突处理。

**验收**

- 修改时间后条目移动到对应日期分组。
- 删除后 5 秒内撤销可恢复；超时后不可恢复。
- 编辑正文删除标签后，该标签不再出现在该条上。

### FR-09 指标管理

**规则**

1. 设置页提供指标列表，展示名称、单位、是否归档。
2. 新增：名称 1～10 字符、去除首尾空白、不可重复（不区分大小写）、不可包含 `#`；单位 0～6 字符。
3. 可修改名称与单位；修改单位仅影响后续识别，历史数值保留写入时的单位快照。
4. 删除采用归档：不再参与新识别，历史数值继续展示，可恢复。
5. 不允许删除仍在被引用的指标定义（归档即可）。

**验收**

- 新增「体重 / kg」后可被识别；归档后新记录不再识别，旧记录仍显示。
- 修改单位为「斤」后，旧记录仍显示 `kg`，新记录按「斤」识别。

### FR-10 导出与导入

**规则**

1. **JSON 导出**：文件名 `daily-record-YYYYMMDD-HHmm.json`，包含版本号、导出时间、全部指标定义（含归档）与全部未删除条目（含置顶与 `extra`）。标签与数值不单独导出，导入时由正文重建。
2. **Markdown 导出**：文件名 `daily-record-YYYYMMDD-HHmm.md`，按日期分组，每条包含时间、正文、指标摘要；仅用于阅读与归档，不支持导入。
3. **导入**：仅接受本产品导出的 JSON。
   - 校验 `schemaVersion`；不匹配直接报错，不做部分写入。
   - 导入前展示预览：条目数、指标数、时间范围。
   - 模式为「覆盖全部」：导入前自动下载当前数据作为保险，并要求二次确认。
   - 全程单事务：失败则保持原数据不变。
   - 导入完成后重建标签与数值，并展示结果摘要。
4. 导出成功后记录 `lastExportAt`。

**验收**

- 导出 → 清空数据 → 导入，条目数、时间、置顶、指标定义、忽略建议全部一致。
- 导入损坏文件 → 明确报错，原数据完好。
- 导出文件用文本编辑器可读，中文不乱码。

### FR-11 PWA

**规则**

1. 可添加到 Android 主屏幕，独立窗口启动，具备图标、主题色、启动背景。
2. 应用外壳预缓存，断网时仍可打开、记录、搜索、导出。
3. 检测到新版本时提示「有新版本，点击刷新」，不静默替换正在编辑的内容。
4. 适配安全区域与 320px 起的窄屏；键盘弹出时不遮挡输入框与提交按钮。
5. 不申请通知、后台同步、定位等权限。

**验收**

- 飞行模式打开已安装的 PWA，可完成一次记录并在恢复网络后仍存在。
- 从主屏幕启动无浏览器地址栏。

### FR-12 备份提醒

**规则**

1. 设置页显示「上次导出：N 天前」。
2. 超过 14 天未导出，在设置图标上显示小圆点，不弹窗、不打断记录。
3. 从未导出时显示「尚未备份」。

**验收**

- 导出后圆点消失；模拟 14 天后再次出现。

## 8. 数据契约

> 本节只定义数据形状与不变式，不指定数据库与技术实现。

### 8.1 实体

| 实体 | 字段 | 说明 |
|---|---|---|
| `entries` | `id`、`content`、`occurred_at`、`created_at`、`updated_at`、`pinned`、`deleted_at`、`extra` | 正文是唯一真相 |
| `tags` / `entry_tags` | `id`、`name` / `entry_id`、`tag_id` | 派生数据 |
| `metrics` | `id`、`name`、`unit`、`archived`、`created_at` | 用户定义 |
| `entry_metrics` | `id`、`entry_id`、`metric_id`、`value`、`unit`、`raw` | 派生数据，`unit` 为写入时快照 |
| `kv` | `key`、`value` | 草稿、`lastExportAt`、`schemaVersion` |

### 8.2 不变式

1. 所有时间以 UTC 毫秒存储，展示与分组按本地时区。
2. 标签与指标数值只能由正文派生；每次保存、导入后**整条重建**（先删后插，单事务）。
3. 删除一律软删除，MVP 不做物理删除。
4. ID 使用 UUID，永不复用。
5. 正文不做任何隐式改写。
6. 派生数据不一致时，以正文为准重建，而不是反向修正文。

### 8.3 导出格式（JSON，schemaVersion = 1）

```json
{
  "schemaVersion": 1,
  "app": "daily-record",
  "exportedAt": 1763337600000,
  "metrics": [
    { "id": "uuid", "name": "体重", "unit": "kg", "archived": false, "createdAt": 1763337600000 }
  ],
  "entries": [
    {
      "id": "uuid",
      "content": "今天很累，体重 70.5kg #健康",
      "occurredAt": 1763337600000,
      "createdAt": 1763337600000,
      "updatedAt": 1763337600000,
      "pinned": false,
      "extra": { "ignoredSuggestions": [] }
    }
  ]
}
```

## 9. 非功能需求

| 类别 | 要求 |
|---|---|
| 性能 | 已缓存状态下冷启动 ≤ 2 秒（中端 Android）；输入回显 ≤ 100ms |
| 容量 | 1 万条记录下时间线滚动不卡顿；列表分页 50 条 |
| 持久性 | 写入必须在本地事务提交后才反馈成功；失败保留正文 |

| 可访问性 | 可点击区域 ≥ 44px；正文对比度 ≥ 4.5:1；图标按钮有可读标签 |
| 语言 | 仅简体中文 |
| 工程约束 | 遵循 `agent.md`：每次改动必须有测试且全部通过，并立即 commit |

## 11. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 指标自然语言识别误判 | 错误数据、用户不信任 | 单位白名单、只提示不自动建档、可忽略；必要时降级为手动添加 |
| 浏览器存储被清理 | 全部记录丢失 | 导出/导入作为发版门槛；14 天未备份轻提示 |
| 范围膨胀 | 主路径变慢、验证失败 | P1 池冻结，新增需求只能替换不能追加 |
| 派生数据与正文不一致 | 搜索/筛选结果错误 | 保存与导入时单事务重建；以正文为准 |
| PWA 缓存旧版本 | 用户看到旧 bug | 更新提示 + 设置页显示版本号 |
| Android 键盘遮挡输入 | 无法提交 | 使用可视视口适配，真机验证 320～430px |
| 首版过度打磨视觉 | 延后验证 | 先可用后好看，视觉风格另行评审 |
